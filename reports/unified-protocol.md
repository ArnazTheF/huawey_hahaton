# Единый протокол: реализация первого пункта

Готово: action — вложенный объект, state_patch — необязательный объект. Протокол
unified-v1 одинаков для history/state/hybrid. Схема памяти и функция слияния
сохранены; валидность действия проверяется до применения патча. Ошибки
структуры отмечаются отдельным событием response_error.

Контроль воспроизводимости: --response-protocol legacy возвращает прежние
промпты и логику контекста. Файл legacy_context.py и старый SYSTEM защищены
проверкой хешей. В metadata новых прогонов явно указан выбранный протокол.

Проверка: 34 теста прошли внутри read-only Docker с --network none, 4 CPU,
16 ГБ RAM. Включены:

- единый system prompt для трёх режимов;
- все типы действий, отсутствие и пустой патч;
- отклонение неправильных аргументов, неизвестных полей и повторяющихся JSON-ключей;
- атомарность отклонённого ответа и отсутствие выполнения опасного тестового действия;
- сохранение наблюдения при повторной попытке;
- прежние правила слияния, удаления, размера и сохранения состояния;
- воспроизведение 13 принятых ответов реального сложного state-прогона с теми же состояниями;
- сквозная сдача одинакового ответа во всех шести сочетаниях протокола и памяти;
- существующий workflow openJiuwen и запуск CLI с подставным HTTP-ответом.

Лог: UNIFIED_PROTOCOL_TEST_RESULTS.txt. Платные API-вызовы не выполнялись.
Следовательно, регрессии структуры/логики в этих проверках не обнаружено,
но изменения расхода и успешности реальной модели ещё не измерены.

Следующий эксперимент: legacy-history, unified-history, legacy-state,
unified-state на одинаковых задачах и бюджетах, несколько повторов. Цена общей
оболочки и общих инструкций должна учитываться в реальном расходе, а не
вычитаться из результатов. Контроль input-estimator — отдельная абляция.
