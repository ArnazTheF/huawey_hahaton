## Исправление после пилота

В v1 hybrid показывал прошлое действие без оболочки state_patch/action. Это создавало противоречивый пример ответа. Формат исправлен; ошибки патча теперь сохраняют последнее полезное наблюдение. Результаты v1 оставлены неизменными и не характеризуют исправленный hybrid.

Контрольный прогон исправленного hybrid на coding и отсутствующих данных: 1125.5 токена. Ошибок внешнего JSON-формата на coding больше не было. Код исправлен, unittest прошёл на восьмом шаге, но агент не успел сдать final до max_steps. Поэтому баллы за coding — 0, согласно правилам сдачи. Отсутствующие данные распознаны.

Общий расход двух экспериментов: 8921.5 эквивалентных выходных токенов.

## Ограничения

- Один прогон на задачу и режим, temperature по умолчанию провайдера, порядок режимов фиксирован. Статистического вывода нет.
- Четыре выполнимых задачи и одна простая невыполнимая. Это проверка инфраструктуры и ранняя оценка стоимости.
- Цепочка из десяти файлов не завершена ни одним режимом при восьми шагах. Программный обход допустим, но режимы им не воспользовались для успешной сдачи.
- Holdout seed=97 не запускался. Он содержит другие данные тех же генераторов, а не новые семейства задач.
- Проверка Python-кода поддерживает test_mylib.py либо unittest discovery. Произвольные языки/системы сборки ещё требуют расширения валидатора.

## Решение

Оставить history по умолчанию. State/hybrid доступны для экспериментов. На коротком наборе state не дал больше баллов и стоил на 42.8% больше. Следующая честная проверка: новые семейства и длинные задачи, одинаковые увеличенные лимиты для всех режимов, несколько повторов. Отдельная абляция — уменьшение патча и предотвращение повторных чтений. Данные holdout не использовать для подбора промптов.
