# State-v2: реализация и полное сравнение

Все четыре пункта плана реализованы и отдельно проверены на полном реестре.
Адаптированный профиль зафиксирован до повторного контрольного прогона.
Проверка завершена: новая версия превосходит исходную по баллам, числу решённых
задач и расходу в обоих полных прогонах на этом наборе.

| Версия | Выполнимых решено, повтор 1 / 2 | Баллы, повтор 1 / 2 | Средний расход серии |
|---|---:|---:|---:|
| Исходный state | 21/26 / 22/26 | 59/81 / 65/81 | 31008.5 |
| State-v2 | 24/26 / 23/26 | 73/81 / 68/81 | 22151.2 |

Всего **47/52 решённых попыток против 43/52**, баллы **141/162 против 124/162**,
расход ниже на **28.6%**. Это повторения одного набора, не 52 независимые задачи.
В каждой серии обработаны все 29 вариантов; три невыполнимых контроля считаются
отдельно. Второй запуск новой версии выполнен из готового Docker-образа без
mounts исходников. Он слабее первого; улучшение не следует считать безусловным.

[Поимённые исходы всех задач в обоих повторах](../runs/state-v2/confirmation.md),
[полные данные](../runs/state-v2/confirmation.json).
Проверенный образ: **`huawei-state-v2:tested`**, тот же image ID, что у кандидата
при полном API-прогоне. [Хеши и происхождение](../runs/state-v2/release.json).

## Что изменилось

1. Действие и patch состояния возвращаются одним запросом с `response_format`
   JSON Schema. Прокси проверен реальным коротким вызовом; валидатор на стороне
   агента сохранён. Модель видит фактический лимит генерации, а в финальной фазе
   схема разрешает только завершение или пропуск. Это не бесплатный retry и не
   гарантия от обрезания длинного ответа.
2. Инструмент `edit` атомарно заменяет ровно одно точное совпадение. Неоднозначное
   совпадение, изменение тестов и выход из рабочей папки отклоняются. Полная
   запись файла и Bash остаются доступны.
3. Ограниченное состояние прогресса содержит следующий шаг, факты со ссылками
   на наблюдения, неудачные подходы, оставшуюся работу и кандидат ответа.
   Дополнительные поля зависят от публичного типа задачи; неизвестный тип
   получает общий fallback. Отдельных модельных запросов для памяти нет.
4. Host хранит происхождение последних результатов команд и хеши прочитанных
   файлов. Изменение постороннего файла не делает чтение устаревшим. Для Bash
   зависимости обозначены как неизвестные: успешная команда не равна правильному
   ответу. Модель не может патчить эти сведения. Повтор чтения — сигнал, а не
   автоматическое признание задачи невыполнимой.

Ограничения памяти и короткие выдержки означают, что это не архив всего вывода.
Большие промежуточные данные нужно сохранять в файлы и обрабатывать скриптами.
Модельные факты и candidate остаются гипотезами, даже если поле имеет правильный
тип; корректность ответа устанавливает внешний оценщик.

## Как выбрана конфигурация

Последовательные версии: исходный контроль → Schema → edit → progress → precise
evidence. Их полные результаты, включая неудачные версии, сохранены в
[поимённой матрице](../runs/state-v2/report.md) и
[машиночитаемом отчёте](../runs/state-v2/results.json).

| Версия, первый полный прогон | Решено выполнимых | Баллы | Расход |
|---|---:|---:|---:|
| Исходный state | 21/26 | 59/81 | 31427.8 |
| JSON Schema | 24/26 | 73/81 | 23733.1 |
| + edit | 23/26 | 69/81 | 26468.2 |
| + progress | 21/26 | 62/81 | 29912.1 |
| + precise evidence | 23/26 | 69/81 | 20800.4 |
| Адаптированный профиль | 24/26 | 73/81 | 21723.3 |

Расход — `input_tokens / 10 + completion_tokens`, не доллары; reasoning=0.
В него входят ошибочные ответы и три невыполнимых контроля. 26 — число
выполнимых задач, 29 — полный размер каждой серии. Контрольные пропуски
показываются отдельно, не добавляются к числу решённых задач.

Расширенная память помогла search, но мешала coding: исходный контроль решил
3/5 coding, Schema — 5/5, progress и precise — 2/5. Поэтому финальная политика:
coding использует простой state + Schema; data/math/search/generic — ограниченный
progress + precise evidence + edit. Это детерминированное правило по типу,
не обученный предиктор и не дополнительные платные вызовы маршрутизатора.
Оно не зависит от наличия истории на закрытой проверке.

Дополнительно убран избыточный учёт переданной JSON Schema как текста сообщений
в предварительной оценке входа. Оценщик продолжает калиброваться по фактическому
usage; реальный расход по-прежнему учитывается целиком. Replay 178 сохранённых
запросов уменьшил среднюю абсолютную ошибку оценки с 2319 до 999 входных токенов
без занижений на этом replay. Это разработческий replay, не гарантия для других
провайдеров. Консервативный режим сохранён флагом `--schema-accounting conservative`.

Адаптированный профиль меняет сразу политику доменов и оценку входа: это совместная
настройка, её выигрыш нельзя причинно приписать только надёжности памяти.
В первом прогоне отклонённые ответы уменьшились с 33 до 1, одинаковые повторные
direct-read фрагменты — с 52 до 15. Счётчик чтений не включает чтение внутри Bash
и сам по себе не доказывает бесполезность повторения.

## Условия и честные ограничения

Реестр: 29 уникальных вариантов из 37 папок, включая исходные примеры и все
различающиеся сгенерированные данные. Это знакомый разработческий набор;
независимого скрытого holdout нет. Варианты одной задачи зависимы. Два повтора
не устанавливают статистическую значимость и не гарантируют перенос на закрытые
задачи. Промежуточные версии имеют по одному полному запуску, профиль выбирался
по этим результатам; повторная проверка фиксированного профиля отделена от выбора.

Модель `qwen3.8-27b-noreason`, 2500 эквивалентов на задачу, 24 вызова, максимум
900 output tokens, 180 секунд на задачу. Бюджет серии 72500 покрывает все
потолки задач; поздние задачи не голодают из-за малого общего бюджета.
API-вызовы идут в Docker последовательно. Sampling — default провайдера.
Эталонные метаданные и hidden tests остаются снаружи; grading внешний.
Снимки исходников, настройки, ответы, инструменты и usage сохранены для всех
серий. Реплики контроля запускаются на исходном неизменённом снимке.

Первые попытки precise evidence прерывались HTTP 429 и затем транспортной
ошибкой. Они сохранены отдельными сериями, исключены из сравнения качества,
расход не скрыт. Для неопределённого запроса отдельно выделен резерв 1325:
это не подтверждённое списание. После ошибок серии повторены последовательно.
Отсутствие usage для HTTP 429 не доказывает нулевую сумму в счёте провайдера.

Первая проверка упакованного профиля также прервалась HTTP 502 на второй задаче.
Одна задача была решена, 27 не начаты; подтверждённый usage 687.1 сохранён.
Эта попытка не включена в качество. Полный повтор прошёл без инфраструктурных
ошибок. Без usage самого ответа HTTP 502 его фактическое списание неизвестно.
По всем сериям и capability probe: известный usage **218709.5**, отдельно резерв
неопределённого запроса **1325.0**, учтённая сумма **220034.5**. Исходный потолок
362500 не увеличивался; неизвестные списания по HTTP-ошибкам не объявляются нулём.

Два провала первого адаптированного прогона:

- `intervals_and_ledger__7cffed5eb9bc`: видимые тесты прошли, внешний hidden test
  обнаружил ошибку выбора записи при равных ревизиях. Это алгоритмическая ошибка,
  которую память/Schema не устраняет автоматически.
- `versioned_route__1e4daf48d476`: пропуск по оставшемуся бюджету выполнения.

Ответы именно этих задач не зашиты в агент; будущие проверки должны сохранять
весь набор и поимённую отчётность, а не выбирать удачные случаи.

В повторном прогоне образа не решены:

- `intervals_and_ledger__7cffed5eb9bc` — остановка по бюджету задачи;
- `stable_toposort__5697c44df16a` — остановка по бюджету задачи;
- `versioned_route__1e4daf48d476` — сдан неверный итоговый ответ.

Тот же вариант versioned_route не решён ни в одном из двух новых прогонов,
хотя другие search-варианты решены. Coding и длинные цепочки остаются слабыми
местами. Data-analysis 8/8 и выполнимая math 6/6 пройдены в обоих новых запусках.
Отклонений протокола стало 1 и 4 против 33 и 37 в контроле; это улучшение,
но надёжность канала всё ещё не абсолютная.

Пропуски невыполнимых контролей оформлены правильно в 2/3 случаев у обеих
версий в обоих повторах. На `inconsistent_integer` модель каждый раз правильно
написала, что целого решения нет, но выбрала `final`, а не `skip`. Это ошибка
оформления пропуска, а не математическая ошибка. Без дополнительной проверки
нельзя считать фильтр невыполнимости полностью надёжным; автоматического
пропуска по стоимости, похожести или повторному чтению не добавлено.

## Воспроизводимость и запуск

Профиль: [configs/recommended.json](../configs/recommended.json).
Обычный запуск с текущим кодом:

```bash
python3 scripts/prepare_run.py --source task-dir --dest runs/my-state-v2/tasks
python3 scripts/run_docker.py --tasks-dir runs/my-state-v2/tasks --budget 20000
```

`20000` — пример лимита запуска, не обещанный бюджет соревнования. Приложение
само `.env` не читает; Docker получает его через `--env-file`. Общий бюджет
устанавливайте по фактически доступному лимиту. `--profile baseline` в wrapper
включает старые defaults; для честного сравнения задавайте одинаковые caps.

Для новой полной оценки исходного state и рекомендованного профиля:

```bash
python3 scripts/benchmark.py --suite all --comparison solution \
  --out runs/all-next-v1 --repetitions 2
```

Верхний предел такого нового платного сравнения — 290000; `--resume` повторно
использует завершённые серии. Профильные caps заменяются общими caps сравнения.
Никакие частные диагностические вызовы не заменяют полный прогон.

Сборка с уже установленными зафиксированными зависимостями без скачиваний:

```bash
docker build --pull=false --network none -f Dockerfile.release \
  -t huawei-state-v2:candidate .
```

Проверенный образ уже есть локально. Запуск именно его, без mounts исходников:

```bash
python3 scripts/prepare_run.py --source task-dir --dest runs/packaged-v2/tasks
docker run --rm --env-file .env \
  -e LLM_BASE_URL=https://api.neuraldeep.ru/v1 \
  --read-only --tmpfs /tmp:rw,size=2g \
  --cap-drop ALL --security-opt no-new-privileges \
  --cpus 4 --memory 16g --pids-limit 512 \
  -v "$PWD/runs/packaged-v2/tasks:/data/tasks:rw" \
  huawei-state-v2:tested --tasks-dir /data/tasks --budget 20000
```

В обычном `Dockerfile` доступна сборка из lock-файла с установкой зависимостей.
В кандидатном образе подтверждено отсутствие `.env`, задач, эталонов и тестов;
встроенный runtime совпадает с рабочими файлами по SHA-256. Офлайн dry-run
увидел все 29 задач. [Аудит образа](../runs/state-v2/image-audit.json).
Инфраструктурные проверки: **100 тестов прошли** в Docker без сети, read-only
FS, без ключей API. [Полный лог](../STATE_V2_TEST_RESULTS.txt).
