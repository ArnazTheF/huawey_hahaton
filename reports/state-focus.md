# State как основная конфигурация: результаты и следующий шаг

Дата: 13 ноября 2026. Все перечисленные платные прогоны выполнены в Docker
huawei-baseline:tested через https://api.neuraldeep.ru/v1. Ключ передан через
--env-file, содержимое .env не читалось и не выводилось. Источники, expected и
hidden_test.py не монтировались в контейнер агента; оценивание выполнено снаружи.
Расход измерен как input_tokens/10 + output_tokens, включая reasoning.

## Сравнение на трёх задачах

| Конфигурация | Решено | Баллы | Расход |
|---|---:|---:|---:|
| qwen3.8-27b-noreason + state | 3/3 | 12/12 | 4633.3 |
| Маршрутизатор + процедурная память + жёсткие квоты + state | 0/3 | 0/12 | 4819.6 |

Лимиты одинаковые: 5000 на серию, 2500 на задачу, 24 шага, 900 output tokens,
180 секунд. Проверка coding включает дополнительные внешние тесты.
Маршрутизатор выбрал full/state на всех трёх задачах; его общий расход 176.3.
Жёсткая reward-weighted квота уменьшила доступный бюджет первых задач.
Одновременно менялись несколько компонентов: причинный эффект отдельного
компонента этим сравнением не установлен. Нельзя утверждать, что маршрутизация
или процедурная память в принципе бесполезны. Интегрированная версия НЕ принята
по умолчанию. advisory pacing реализован без жёсткого урезания, но отдельно
через живой API ещё не оценивался.

Процедурная память — простой лексический поиск по 6 проверенным карточкам,
сгенерированным шаблонными правилами из успешных траекторий. Это приближение
experience retrieval, не полная реализация метода из статьи. Поведенческая память
содержит два семейства наблюдений; правильные ответы и внешние оценки в запрос
маршрутизатору не передаются. Семейство текущей инструкции исключается из памяти.

Набор здесь — три прежних семейства с изменёнными данными, один повтор;
это не доказательство обобщения на закрытый тест и не новое чистое сравнение
history/state. Старое преимущество state над history также имело различия
протоколов: см. reports/skillstate-harder-v1.md. History сохранён как контроль.

## Расширенный state-only тест

Новый генератор: scripts/make_broad_experiment.py, данные experiments/state-broad-v1.
Серия: qwen3.8-27b-noreason, state, unified, calibrated, reserve;
без маршрутизации, процедурной памяти, pacing и reasoning.
Лимиты: общий 8000, на задачу 1600, 16 шагов, 900 output tokens, 150 секунд.

| Задача | Внешняя оценка | Расход |
|---|---|---:|
| integer_program: 80 операций с целыми | верно | 363.6 |
| working_days: календарь и исключения | верно | 294.7 |
| lower_median: фильтрация, дубликаты, нижняя медиана | верно | 383.1 |
| manager_office: поиск по связям и отвлекающим данным | верно | 200.2 |
| stable_toposort: исправление кода | верно; 4 дополнительных теста | 1150.9 |
| snapshot_revenue: ревизии, ничьи, CSV | не сдано; бюджет и обрезанные ответы | 1177.8 |
| missing_amounts: отсутствующие исходные суммы | корректный skip, 11 вызовов | 1091.7 |
| inconsistent_integer: несовместимые ограничения | final «no solution», не skip | 71.6 |

Итого: 5/6 выполнимых, 15/19 доступных за них баллов; расход 4733.6,
34 вызова. Невыполнимые задачи не добавлены в числитель решённых.
Формальный оценщик помечает inconsistent_integer как passed=false: отдельный
просмотр показывает правдивое сообщение о противоречии без выдуманного числа,
но протокол явного skip не соблюдён. Нельзя называть это 2/2 correct_skip.
Это синтетические задачи; по одному запуску, без оценки дисперсии.

## Диагностика большого вывода

Отдельно повторили snapshot_revenue, изменив только tool-output-chars с 12000
до 2400. Остальные лимиты сохранены; задача запущена отдельно, поэтому отсутствует
калибровка оценщика на предыдущих задачах серии — это дополнительное отличие.
Расход 1266.5, 5 вызовов, 0 баллов; причина insufficient_budget_for_request.
Агент записал solve.py и получил правильное 438293, затем перечитал CSV без
сохранения результата в state_patch и пытался вычислять заново. Это наблюдение
поддерживает гипотезу о потере полезного результата; не доказывает единственную
причину провала. Меньший лимит вывода НЕ принят по умолчанию.

## Текущее решение и ближайшая абляция

Основная конфигурация: state + qwen3.8-27b-noreason. Маршрутизация, experience,
pacing, loop-policy выключены. --reasoning-budget 0 запрещает reasoning-модели.

Следующее изменение для отдельного обсуждения и реализации: компактная память
последних вычислений и проверок, управляемая хостом, плюс краткий список уже
проверенных действий. Хранить ссылки на наблюдения, stdout и коды завершения
с жёсткими лимитами размера; успешный exit code не считать доказательством
правильности. Нужны обработка устаревания после изменения файлов и одинаковый
общий бюджет. Не сохранять полный transcript и не превращать повторение
действия в автоматическое доказательство невыполнимости.

Проверять по одному изменению, повторными запусками на отложенных семействах:
баллы, доля успешных задач, полный расход включая неуспехи, повторные действия,
потери уже вычисленного ответа. Цена на решённую задачу вторична к общему счёту.

Это не оценка качества моделей; малый cap может исчерпаться на reasoning.

её для вывода о неспособности reasoning решать coding.
